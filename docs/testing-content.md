# Тестування та повернення початкового наповнення

Початковий шаблон контенту вже збережений у `home/seed_content/`. Це тексти, структура сторінок,
обидві мови, секції, публікації, зображення та налаштування оформлення.

## Простий процес

Для готових навчальних прикладів (англійською і чеською) запустіть:

```powershell
& .venv/Scripts/python.exe manage.py seed_biglab_demo
```

Після запуску відкрийте http://127.0.0.1:8000/wagtail-showcase/ або чеську версію
http://127.0.0.1:8000/cs/wagtail-showcase/. Каталог містить різні розміщення тексту й фото,
галереї, GIF, slider, comparison, відео, симуляцію, профілі, новини, проєкти, вкладені
сторінки, спільні записи та інструкцію. Частина матеріалів навмисно залишена чернетками.
Кожен опублікований приклад має посилання на його редактор Wagtail.

Результати перевірки й відомі обмеження: [перевірка навчального набору](wagtail-demo-audit.md).

Повторний запуск додає відсутні приклади й зберігає редакторські правки в наявних.
Команда не запускається під час старту чи деплою. Для повністю свіжих прикладів
спочатку виконайте скидання нижче, потім знову `seed_biglab_demo`.

1. Тестуйте CMS на звичайному локальному сайті: http://127.0.0.1:8000/admin/.
2. Створюйте тестові сторінки й підсторінки, змінюйте секції, завантажуйте фото, додавайте публікації.
3. Щоб повернути весь контент до початкового шаблону, з кореня проєкту виконайте:

```powershell
& .venv/Scripts/python.exe manage.py seed_biglab --reset
```

Команда видаляє додані тестові матеріали та відновлює контент із `home/seed_content/`.
Облікові записи, пароль адміністратора, домен і основні права редакторів зберігаються.
На сервері використовується та сама команда: `python manage.py seed_biglab --reset`, запущена
в контейнері відповідного сайту. Команда працює з базою середовища, у якому її запущено.

Під час тестування залишайте `home/seed_content/` без змін. `export_biglab_content` замінює
початковий шаблон поточним наповненням; запускайте його лише для свідомого оновлення шаблону.

## Готовий сайт

У Railway задайте змінну сервісу `SEED_INITIAL_CONTENT=0` і застосуйте зміни.
Тоді після перезапусків і деплоїв запускаються тільки міграції та вебсервер.
Нові сторінки, публікації й редагування замовників зберігаються.
Повний reset запускається тільки вручну з прапорцем `--reset`.

## Попередня тестова копія

Порт 8020 — окрема копія, створена раніше для тестування зі збереженням робочої бази.
Для простого процесу вище використовуйте порт 8000. Раніше створений архів залишився
локально в `.impeccable/manual-testing/baseline/`; для нової команди reset він не потрібен.
